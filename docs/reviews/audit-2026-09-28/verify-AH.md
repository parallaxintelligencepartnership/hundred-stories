### S1. ship.sh treats a failed deploy as success, then pushes and tags - CONFIRMED (final: IMPORTANT)
- Reproduction: scratchpad/verifyAH/ship/ holds a scratch git repo with the version files, two local bare remotes standing in for origin and github, a copy of scripts/ship.sh (only the log path moved into the scratchpad), and a stand-in `npm` on PATH that fails `run deploy` with a fake TS error and exit 2. Running `sh scripts/ship.sh 0.6.9 ship-test` printed the error, then `pushing`, then new branch and tag to both remotes, then `shipped 0.6.9 as ship-test` with exit 0. Both bare remotes then held tag ship-test and commit "0.6.9". With `set -o pipefail` added after line 5 (macOS /bin/sh is bash 3.2, which accepts it), the same run stopped at the deploy with exit 2 and pushed nothing. The commit and tag (:55-56) still stay local, and a re-run is refused (":24 package.json is already", ":18 tag exists"), so after a false "shipped" the script cannot redo the ship.
- Rubric: this is owner-facing, and the live site stays on the last good version. It lands on the IMPORTANT line "a failure path that throws instead of showing the plain message", read for the deploy path: the failure is reported as "shipped". Decision 2026-09-27 ("the ship script is the deploy path from now on and Claude runs it") makes this the only path, and the ship record in DECISIONS and SHIPPED is written from its output. The public mirror then carries a tag for a release that is not live. Under a strict player-only reading it would be ADVISORY. I rule IMPORTANT because of the false record and the dead re-run.
- Fix spec: make the deploy's exit status stop the script. Either add `set -o pipefail`, or run `npm run deploy >log 2>&1 || { cat log; echo "deploy failed; local commit X and tag T not pushed"; exit 1; }`. Better still, move the tag after a successful deploy. Before any bump, refuse unless `git rev-parse --abbrev-ref HEAD` is main. A test such as tests/site/ship-script.test.ts should run the script against a scratch repo with a failing npm stub and assert a non-zero exit, no push to either remote, and no "shipped" line. That test fails today and passes after the fix. Unchanged: the bump set, the tag naming, and the push order.

- Reproduction: at 0f05723, ten dependency entries read `version = "0.6.6"`: block2, cssparser-macros, jsonptr, objc2, raw-window-handle, socket2, string_cache_codegen, toml_datetime (the first of its three entries), window-vibrancy and writeable. Separately, restore the ten entries to the versions above. Add a guard to versions.test.ts that either compares every non-app `[[package]]` version and checksum pair against a snapshot, or fails when any crate other than hundred-stories carries the app version.
