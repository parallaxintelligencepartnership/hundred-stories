# Hundred Stories - shipped 2026-09-19

## What this is
Hundred Stories is a browser game and installable PWA (paid store editions planned, the web build is the full game): a tower-building sim with illustrated art drawn in code, inside a pixel grid, a from-scratch homage to SimTower. The code and art are original and the game design is not; there is a deterministic sim core underneath. You run a skyscraper: build a lobby, offices, homes, shops and elevators, watch it fill with people over the years, and climb the star ladder from one star to TOWER. There is no backend and no account: the whole game runs in the browser, and saves live in the player's own browser storage plus files they export themselves. The site at https://hundredstories.xyz is a static landing page with search and share metadata; the game lives at `/play/`. One code base builds three editions from `VITE_EDITION`: `web` (the site, uncapped, what hundredstories.xyz serves), `demo` (floors 1 to 20, basements to 2, the middle 150 tiles, with a card pointing at the stores) and `full` (the store game). The same game page is wrapped for the stores: Capacitor shells for iOS and Android and a Tauri desktop shell for Steam with star achievements behind the `steam` cargo feature; they are built to submission ready (store/SUBMISSION.md) and nothing is submitted. Since the look and UX rounds the game has 16 px tiles, an hour-tinted light layer, animation and synthesized sound (off by default), a first-run intro and guide, goals, information views, hover cards, keyboard groups and a minimap. Source is public to read under PolyForm Strict 1.0.0 (personal, noncommercial use, no redistribution or derived products; releases tagged before 2026-09-20 remain AGPL-3.0) at https://github.com/parallaxintelligencepartnership/hundred-stories.

## How to run it
Requirements: Node 26 (pinned in `.nvmrc`). No environment variables.

```bash
npm ci
npm run dev       # landing on http://localhost:5173/, game on http://localhost:5173/play/
npm test          # vitest run: 2241 tests in 181 files (2241 pass, 1 skipped plus store screenshot skips as before: the opt-in store screenshot run needs Chrome)
npm run typecheck # tsc --noEmit
npm run audio:samples && node scripts/analyze-audio-samples.mjs docs/reviews/audio-samples-2026-09-23/*.wav  # the score gate, every line PASS or SKIP
npm run build     # tsc --noEmit then vite build, output in dist/ (landing, how-to-play, play, privacy, 404)
npm run preview   # serve the production build on http://localhost:4173 (does NOT send public/_headers)
npm run build:demo # the demo edition (size cap on) into dist/; build:full is the uncapped store edition
npm run build:app  # the game page alone into dist-app/ for the Capacitor and Tauri shells (cap:sync, npx tauri build)
```

`?seed=<number>` on the game URL opens a friend's tower in the Friend's tower slot (players never see the number; the share link carries it), `?daily` opens Today's tower, `?new` starts a fresh My tower. To test the security headers, run the nginx container from `deploy/cloudflare-pages.md` (Verification section); the Vite servers do not enforce them.

Running the suite somewhere other than the dev Mac: rsync the tracked tree to a Linux host with Docker and run `npm ci` and `npx vitest run` in a `node:26-bookworm-slim` container with the tree mounted at the same absolute path it has on the Mac (probe scripts under `docs/reviews/` import `src/` by absolute path). The 0.5.0 closeout ran every test, the typecheck, the build, the rollback rehearsal and the browser probes that way on pi2 (x86_64, 8 cores); the recipe is in `.itworks/MAP.md` under Environment.

## How to deploy an update
Hosting is Cloudflare Workers static assets (the successor to Pages): asset requests are free and unlimited, headers from `public/_headers`, custom domains declared in `wrangler.jsonc`. Runbook: `deploy/cloudflare-pages.md`.

Since the feedback card, the site is a Worker with static assets (`src/worker/index.ts`, `main` in `wrangler.jsonc`). Files are still served before the Worker runs for everything except `/trailers/*` (`run_worker_first: ["/trailers/*"]`, so Safari and iOS get the 206 partial content those videos need), so pages, headers and the 404 page behave as before; the Worker answers only `POST /api/feedback` (and its CORS preflight): it validates the message, rate limits 2 posts a minute per IP (binding `FEEDBACK_LIMIT`), then 3 a minute for all senders together (binding `FEEDBACK_GLOBAL`, key `global`), and stores text, reply address, version, platform, screen and time in the KV namespace `FEEDBACK` (no IP or user agent). The shared limit bounds KV writes to 4,320 a day at most; if the KV free tier's daily write cap (about 1,000 a day) is passed anyway, the Worker answers 507 "full for today" and the player sees the card's "Feedback is full for today. Try again tomorrow." line. The web page posts to its own origin; the app shells post to https://hundredstories.xyz/api/feedback from their own origins, which the Worker allows by name (`ALLOWED_ORIGINS`: capacitor://localhost, https://localhost, tauri://localhost, http://tauri.localhost and the two site hostnames); any other Origin gets a 403. 404 requests, `/api` and every `/trailers/*` request count toward the free 100,000 Worker requests a day; other pages and files never do. Messages wait in KV until the mailer on the tailnet reads them; `npx wrangler kv key list --binding FEEDBACK --remote` to look. `npx wrangler deploy --dry-run --outdir /tmp/hs-worker-dry` bundles the Worker without deploying.

```bash
npm run deploy    # npm run build && node scripts/predeploy-check.mjs && npx wrangler deploy (wrangler 4.135.0, pinned)
```

`scripts/predeploy-check.mjs` (since 0.5.0) refuses to deploy a build whose `dist/_headers` policy would allow eval, whose play page is missing, or whose bundles lack the PixiJS unsafe-eval shim (`_unsafeEvalCheck(){}`); that is the static form of the check that would have caught the first live defect. Before a deploy that touches the renderer, the CSP or PixiJS, also load `/play/` from the nginx container in headless Chrome and check the console for `Refused` or `unsafe-eval`. Verify after: `curl -sI https://hundredstories.xyz/` shows the five headers, `/nope` is 404, `http://` redirects to https, and `/play/` mounts a canvas.

Fallback, pi3 (`deploy/README.md`): copy `deploy/.env.example` to `deploy/.env`, set `SITE_HOST`, run `deploy/deploy.sh`. The fallback nginx now serves `404.html` for missing paths, like the primary.

- OUTSTANDING, IMPORTANT, production-readiness: no whole-application audit since 2026-09-25 @7b4e60f; 0.6.8 is the tenth ship since then. The 2026-09-27 acceptance ("accept it tonight") has expired and the finding is open, not accepted; the audit is the next piece of work.
- Money: office rent is set by the office's resting rating at the 5 AM settle; running costs are charged in full for whatever exists at the settle; offices lease on weekday mornings only; a sold condo cannot be demolished; demolition refunds a quarter of the build price. Rulings in DECISIONS.md 2026-09-28.
- Video byte ranges: /trailers/* run the Worker first, so every video request counts against the Workers plan's request allowance; the assets path stays free for everything else. Revisit when: the next session on this project, with a `project-audit` pass before further feature work.

Try again tomorrow." Accepted as designed 2026-09-28 (DECISIONS.md); the failure mode is bounded and cannot bill.
- Evening rush, 0.6.9: the rush is spread 4:30 to 7:30 PM with one quitting time per company, offices arrive 7:30 to 9:15 AM, residents come home 5:00 to 9:30 PM, so existing towers run a little differently after 0.6.9 (DECISIONS.md 2026-09-28).

## What breaks first and how you'd know
The News panel, or any other sheet, losing its taps to a shared CSS class, first. A sheet that ends up carrying a toast region's class (as the News panel did once, live since the 2026-09-25 ship until the 2026-09-28 playtest fix) inherits that region's `pointer-events: none`, absolute position and transform, so every tap on it falls through to whatever is underneath and the sheet cannot be closed by any pointer path at 900 px and wider. `tests/ui/toast.test.ts` guards the class boundary and the pointer-events rule; if that guard is ever reverted, players will report a panel, sheet or button that "lights up" or opens but will not respond to taps.

Second: a PixiJS upgrade that changes how it compiles shaders. The site's Content Security Policy forbids eval, and the renderer only starts because `src/render/renderer.ts` loads `pixi.js/unsafe-eval` before anything else; if an upgrade moves that requirement, `/play/` shows "Something on our site stopped the tower from loading. It is our mistake, not your browser. Please try again later." and the browser console logs `unsafe-eval`. Two things catch it before players do: `scripts/predeploy-check.mjs` stops `npm run deploy` when the shim is missing from the bundles, and the nginx-container console check in `deploy/cloudflare-pages.md` shows the refusal.

Player error reports stay minimal: the privacy page promises no collection of what a player types or does, and the site only carries Cloudflare Web Analytics (the `cfBeacon` snippet, since 2026-09-26), which counts visits and does not report script errors. A player's own report through the feedback card, or the console checks above, is still the signal for anything that gets past the gates. A browser whose IndexedDB never opens is unchanged from earlier ships: since 0.5.0 a failed read no longer starts a fresh tower over the player's save; a returning player sees "We could not read your saved tower. Reload the page to try again." and the slot stays protected until a read succeeds. The fonts are self-hosted (`src/fonts.css`, `font-src 'self'`), so a font CDN outage cannot break the pages.
